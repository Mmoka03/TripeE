- `frontend/public/design/gsap.min.js`, `ScrollTrigger.min.js`: GSAP·ScrollTrigger 3.13.0.

- 지도·로딩 안내·탐색 도구의 표시 순서를 분리함. 모바일 상세 패널 아래에도 지도 출처 공간을 확보함.

## 다수 도시 탐색 시안

- 기본 3개, 인접 검수 2개, Natural Earth 추가 240개를 합쳐 245개 도시로 검수함.
- 추가 데이터: https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_110m_populated_places.geojson
- 이름·좌표만 검수에 사용함. 여행 정보가 게시된 도시 목록이 아니며 국가·도시 표기 검수는 별도임.
- 기본/인접 도시와 이름이 중복되는 추가 데이터는 제외했음.
- 개별 도시는 접힌 지도 아이콘이 들어간 작은 여행 태그로, 밀집 도시는 도시 수가 적힌 티켓형 표식으로 표시함. 반복되는 원형 테두리를 제거했음.
- 화면상 묶음 중심 간 거리를 기준으로 가까운 묶음부터 합침. 기준 거리는 PC 64px, 터치 환경 72px이며 핀 크기에 따라 최대 98px까지 늘어남.
- 핀 크기는 75~150%로 조절하며 개별 핀·묶음 핀·아이콘·숫자가 함께 변함. 모바일 터치 영역은 최소 44px을 유지함. 크기·선택 상태 변경 시 기존 표식을 재사용함.
- 확대·축소가 끝나면 원본 도시 좌표로 다시 계산하므로 확대 시 개별 핀으로 나뉨. 같은 좌표의 도시는 목록에서 선택함.
- 공통 도시를 기준으로 이전 묶음과 새 묶음의 중심을 연결해 이동·크기·투명도를 전환함. 등장 420ms, 퇴장 260ms이며 연속 지도 조작 시 이전 전환을 정리함.
- 퇴장 중인 표식은 클릭·키보드·접근성 탐색에서 제외함. 동작 줄이기 설정에서는 즉시 전환함.
- 국가를 넘는 묶음을 허용함. 커서 체류 또는 키보드 포커스 시 도시 수와 국가 수를 안내함.
- 묶음 클릭 시 포함된 전체 도시를 묶음 중심에서 가까운 순서로 표시하고 국가명을 함께 안내함. 모바일은 탭으로 목록 또는 상세를 엶.
- 245개 도시에서 동작 검수한 시안이며 수천 개 도시의 성능을 보장하는 구현은 아님.
- 묶음 계산 검증: node --test frontend/src/cityClusters.test.js

### 표식 디자인 참고

- Mapbox HTML/SVG 묶음 예제: https://docs.mapbox.com/mapbox-gl-js/example/cluster-html/
- Google Maps 선택 시 정보가 펼쳐지는 HTML 표식 예제: https://developers.google.com/maps/documentation/javascript/examples/advanced-markers-html
- 참고한 것은 묶음 표현과 선택 정보의 단계적 노출 방식임. 티켓형 표식은 프로젝트 CSS로 구성했음.
- 선택한 묶음은 PC 오른쪽 여행 카드, 모바일 하단 패널로 펼침. 기본 화면에서는 표지와 닫기 버튼을 고정하고 도시 목록만 스크롤함. 높이 700px 이하에서는 카드 전체를 스크롤하고 닫기 영역을 고정해 목록 공간이 사라지지 않도록 함.
- 교토가 포함된 묶음은 기존 교토 사진을 사용함. 그 외에는 NASA 지구 이미지를 공통 탐색 이미지로 명시함. 다른 도시 사진으로 대체하지 않았음.
- 교토 사진: Tomomarusan / CC BY 2.5 / 크롭. https://commons.wikimedia.org/wiki/File:Arashiyama_Togetsukyo-bridge.jpg
- 이미지 로딩 실패 시 안내를 표시하며 도시 선택은 유지함. Escape로 닫기와 포커스 복귀를 지원함.
- 모바일 패널 아래 지도 출처는 항상 노출함. 320px·390px 및 FHD 화면에서 목록 스크롤과 상세 이동을 검수함.
- 지도에 모아 보기는 목록 상단에, 도시 목록 복귀는 상세 상단에 배치함. 상세에서 돌아와도 검색 필터를 유지하고 선택했던 행으로 포커스를 돌려줌.
- 지도에 모아 보기는 현재 필터에 남은 도시만 대상으로 하며, 검색 결과가 없으면 비활성화함. 목록 복귀·닫기·Escape 모두 선택했던 행으로 돌아옴.
- 검색 결과는 도시 패널보다 앞에 표시하고 화면 높이에 맞춰 스크롤함. 검색으로 이동한 뒤에는 입력창을 접고, 실제 패널 크기를 반영해 도시가 가려지지 않는 위치로 지도를 이동함. 태블릿의 확대·축소 버튼도 상세 패널 옆으로 옮김.
- FHD·1366px·1024px·768px, 모바일 390×844·320×568, 가로 844×390과 높이가 줄어든 390×450 화면을 브라우저에서 검수함. 긴 목록의 스크롤 위치, 검색·국가 필터, 빈 결과, 상세 왕복, 검색 후 표식 노출을 확인함. 실제 휴대전화의 가상 키보드 동작은 별도 기기 검수가 필요함.

## 2번 섹션 스크롤 전환

- SEED의 도형과 UI를 연결하는 구성, Apple의 중심 대상 유지, Lenis의 타이포그래피·여백 전환을 참고했음. 외부 디자인 자산이나 코드는 복사하지 않았음.
- 참고: https://seed-design.io/ · https://www.apple.com/airpods-pro/ · https://lenis.dev/
- 같은 세 면이 접힌 지도 그래픽에서 경험·방문 시기·안전정보 영역으로 변함. 선 그래픽은 실제 지리 정보가 아닌 장식임.
- 왼쪽 문구와 전체 색상, 다른 섹션은 유지함. 이전 확대·클리핑 카드 전환은 제거했음.
- `bridge-story.css`, `bridge-story.js`로 분리하고 예전 시안의 CSS와 충돌하지 않도록 클래스 접두어를 구분했음.
- 화면 고정과 스크롤 진행률 연동을 제거했음. 장면 상단이 화면 높이의 30%를 통과하면 약 2초 동안 자동으로 펼쳐짐. 추가 스크롤 없이 완료됨.
- 위로 돌아가 장면 상단이 화면 높이의 50%를 넘으면 되감음. 두 기준 사이에서는 현재 상태를 유지해 작은 스크롤에 반복 재생되지 않게 함.
- 빠르게 방향을 바꾸면 재생 중인 위치에서 역전환함. 예시 바로 보기는 화면을 강제 이동하지 않고 즉시 완성 상태로 전환함.
- 역스크롤, 예시 바로 보기, 키보드 포커스, 모션 감소, JavaScript 비활성 상태를 확인했음. 모션 감소 또는 JavaScript 비활성 시 완성된 예시를 바로 표시함.
- FHD, 390px, 320px, 가로 화면에서 넘침·글 잘림을 검수했음. 사진과 문구는 도시 정보 구성 예시이며 실제 검토된 여행 콘텐츠를 뜻하지 않음.
- 사진은 세 면의 이동과 동기화된 열별 마스크로 공개함. 접힌 상태에서는 면 사이로 사진이 먼저 비치지 않음.
- 교토 표식은 버튼 형태 대신 지명 타이포그래피로 표시함. 동일한 제목 요소가 지도 중앙에서 사진 위 제목 위치로 이동하며 배경에 맞춰 색상을 바꿈.
- 전환 시작·중간·완료와 역방향, 320px·390px·FHD, 화면 크기 변경, 건너뛰기 및 모션 감소 상태를 확인했음.

## 4번 섹션 카드 전환

- 기존 좌우 배치를 유지하고 왼쪽에 풍경 카드와 정보 카드를 겹쳐 배치함.
- 장면 상단이 화면 높이의 6%를 통과하면 약 1.6초 동안 앞 카드를 뒤로 보내고 정보 카드를 앞으로 가져옴. 첫 사진을 충분히 볼 수 있도록 이전보다 화면 높이의 22%만큼 전환 시점을 늦췄음.
- 앞 카드를 아래로 빼면서 아래쪽으로 기울이고, 뒤 카드의 하단을 완전히 벗어난 순간에 순서를 바꿔 뒤로 넣음. 뒤 카드는 제자리에서 조금만 앞으로 나오며 양옆으로 벌어지지 않음. 사진 교체와 투명도 변화는 사용하지 않음.
- 역스크롤로 장면 상단이 화면 높이의 45%를 넘으면 원래 순서로 돌아옴. 두 기준 사이에서는 현재 상태를 유지함. 화면 크기 갱신으로 재생 중인 애니메이션을 강제로 완료하지 않음.
- 카드 높이의 1.25배에 100px의 여유를 더한 공간이 화면에 들어오지 않으면 자동 전환을 사용하지 않고 버튼으로 넘김. 낮은 가로 화면에서도 첫 사진을 끝까지 볼 수 있도록 함.
- 아래쪽 이동 공간을 확보해 재생 중에도 전환 버튼과 출처를 가리지 않도록 함.
- 페이지 스크롤은 가로채지 않으며 전환 버튼도 제공함. 모션 감소 또는 JavaScript 비활성 시 두 카드를 차례로 표시함.
- 카드 높이는 내용에 맞게 늘어남. 정보 문구는 제공할 항목의 예시이며 검토가 끝난 교토 여행 정보는 아님.
- 새 사진: `frontend/public/design/kyoto-bamboo.jpg` — Bamboo forest Kyoto / lb0104672 / CC0 1.0.
- 출처: https://commons.wikimedia.org/wiki/File:Bamboo_forest_Kyoto.jpg
- 1280px 이미지 약 489 KiB를 사용함. 화면 비율에 따라 가장자리가 잘리며 텍스트 가독성을 위해 어두운 그라데이션을 겹침.
- 정보 카드에는 기존 Tomomarusan의 도게츠교 사진을 사용함. 두 사진의 출처와 이용 조건을 카드 아래에 함께 표시함.
- 정보 카드 사진은 PC 16:9, 모바일 3:2 비율로 표시함. 산·다리·강이 함께 보이도록 잘리는 위치를 조정하고 설명 영역을 정리했음. 카드 우측 상단의 풍경·정보 표시는 제거했음.
- FHD·1024px·390px·320px에서 글 잘림과 가로 넘침을 확인했음. 스크롤·역전환·빠른 방향 변경·버튼·키보드 조작과 모션 감소·JavaScript 비활성 상태를 검수했음.

## 소개 페이지 도시 예제 교체

- 오프닝·2번·4번 섹션에 나폴리·교토·베이징을 서로 다르게 배치함. 같은 탭에서 새로고침하면 각 위치의 직전 도시를 제외함. 6번 섹션의 티켓도 같은 순서로 재배치함.
- `city-examples-data.js`에서 도시명·사진·대체 텍스트·출처·좌표·이동 대상을 함께 관리함. 지도 밀집도 검수용 245개 도시를 무작정 소개 후보로 쓰지 않음.
- 2번 섹션 후보는 한글 1~3자, 공백 없는 영문 1~8자로 제한함. 다른 섹션은 긴 이름을 허용할 수 있으나 추가 시 레이아웃을 별도 검수해야 함.
- 글꼴 로딩 후 시작 좌표를 다시 계산함. 로딩 전 글자 폭이 남아 접힌 장면의 중앙에서 벗어나던 문제를 수정했음.
- 사진 교체는 애니메이션 초기화 전에 완료함. 4번 섹션 앞뒤 사진은 동일 도시의 서로 다른 사진임. 사진을 교체하는 애니메이션으로 변경하지 않았음.
- 브라우저 저장소가 차단되면 무작위 선택은 유지하되 직전 도시 제외는 보장하지 못함. JavaScript 비활성 시 기존 교토 정적 화면을 표시함.
- 예제 사진은 기록 사진이며 현재 현장 상황이나 검수 완료된 여행 정보를 뜻하지 않음. 구성 예시 문구도 유지함.
- 검증: `node --test frontend/tests/intro-examples.test.js`. FHD·1024px·901px·390px·320px에서 세 도시의 중앙 정렬·완료 상태·버튼 겹침·가로 넘침·사진 로딩·연속 새로고침을 확인했음. 모션 감소 상태와 사진 출처 링크도 확인했음.

## 사용자 와이어프레임 갱신본

- 로컬 검수: `/wireframe/index.html`. 원본: `frontend/public/wireframe/frames.js`.
- 소개 6개 섹션과 2·4번 전환 전후, PC 지도·검색·목록·상세, 모바일·작은 화면, 예외 상태와 도시 교체 규칙을 반영함. PC 1920×1080, 모바일 390×844 및 320×568 기준임.
- 사진 외에는 텍스트와 도형으로 구성한 정적 와이어프레임임. 실제 지도 경계·GSAP 애니메이션·Figma 프로토타입 연결은 포함하지 않음. 웹에서 동작을 확인해야 함.
- 기존 Figma 파일: https://www.figma.com/design/j8BgA2aE2QQoOxHm9QMZMN
- 2026-11-14 Figma 데스크톱의 로컬 플러그인으로 `사용자 화면 · 검수용` 페이지에 편집 가능한 화면 21개를 추가했음. 기존 v1 화면은 유지했음.
- 생성: `node tools/wireframe-export/build.mjs <출력 폴더>`. Figma 데스크톱에서 Custom UI 개발 플러그인을 생성한 뒤 제공된 `code.js`·`ui.html`을 넣어 실행함. Figma가 발급한 manifest의 id는 유지함. 패키지의 README와 manifest 설정 예시를 참고함. 현재 페이지 오른쪽에 편집 가능한 프레임을 추가하며 기존 화면은 유지함.
- 가져오기 코드는 외부 네트워크를 사용하지 않음. 사진을 함께 포함함. 최초 가져오기는 Noto Sans KR로 적용했으며, 이후 공식 Pretendard 1.3.9를 설치해 기존 21개 화면의 텍스트 341개를 Pretendard Variable로 변경했음. 새 화면은 추가하지 않았음. 웹 WOFF2와 설치한 TTF의 글꼴 버전은 1.309로 일치함.
- 400·500·600·700을 Regular·Medium·SemiBold·Bold로 구분함. 가져오기 코드에서 500과 600을 같은 굵기로 처리하던 부분도 수정했음. `기존 21개 화면의 글꼴 맞추기`는 원본 화면 구조와 문구를 확인한 뒤 글꼴만 변경함.
- 최초 가져오기 후 PC 소개 전환 후·지도 상세, 모바일 소개 전환 후·도시 상세를 확대해 확인했음. 해당 확인은 Pretendard 변경 전 기준임.
- Pretendard 변경 후 PC 소개 전환 후, 390px 모바일 소개 전환 후, 320px 작은 화면 목록을 확인했음. 주요 UI에서 새로 생긴 글자 잘림이나 겹침은 발견하지 못했음.
- 320×568 작은 화면의 배경 지도 라벨과 묶음 숫자 4는 원본 좌표상 화면 오른쪽을 벗어남. 목록 패널 뒤에 있는 요소이며 글꼴 변경 전에 존재하던 배치임.
- 2026-11-14: 포매터 처리 후 데이터 삽입 표식이 달라져 화면 데이터가 빠지던 패키지 생성 오류를 수정했음. `node --test tools/wireframe-export/build.test.mjs`로 배포 UI의 가져오기 버튼이 21개 화면과 사진 5개의 실제 바이트를 전달하는지 확인함. 반복 실행하면 새 프레임이 추가되므로 같은 화면은 한 번만 가져오면 됨.
