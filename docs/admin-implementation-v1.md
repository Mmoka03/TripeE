# 관리자 구현 범위

2026-11-01 기준임. /admin에서 실행하며 사용자 지도는 / 경로를 사용함.

## 구현한 흐름

- A/B 시연 사용자 선택, 도시 생성·검색·상태 필터를 구현했음.
- 일반 초안에서 기본 정보·태그·사진 메타데이터·권리·경험·출처를 편집함.
- 게시 전 필수 항목을 검사하고 누락 항목의 입력 화면으로 이동함.
- 안전정보 독립 게시와 최신 버전 충돌 재검토를 구현했음. 재검토 저장은 게시와 별개임.
- 일반 초안의 안전정보가 미수정이면 최신 공개 안전정보를 유지함. 수정 중 기반이 바뀌면 전체 게시를 차단함.
- 비공개·준비 중 전환, 초안 폐기, 삭제와 변경 전후 감사 이력을 시연함.

## 편집권

60초마다 연결을 확인하고 5분간 응답이 없으면 잠금이 만료됨. 실제 입력·클릭이 1시간 없으면 시연 세션을 종료함. 열린 화면에서 잠금이 만료되면 입력을 유지하고 저장을 차단함.

재진입 후 본인의 잠금이 남아 있으면 확인을 거쳐 ‘편집 재개’를 선택할 수 있음. 토큰을 교체해 이전 화면의 저장·연결 확인을 차단함. 마지막 저장본만 불러오며 미저장 입력의 복구는 보장하지 않음. 다른 관리자의 잠금은 가져올 수 없음.

## 실제 서비스와의 차이

- localStorage의 tripee.admin-demo.v1에 저장함. 실제 인증·API·PostgreSQL과 연결되지 않음.
- 잠금·버전 검사는 요구사항 확인용 모형임. 다중 요청의 원자성·접근 통제·감사 로그 변조 방지는 서버에서 구현할 예정임.
- 실제 재개 API는 인증된 관리자 소유권과 기존 잠금 버전을 확인하고 토큰 교체를 원자적으로 처리해야 함. 세션 만료를 우회해서는 안 됨.
- 사진 원본은 메모리 미리보기만 지원함. 새로고침 후 원본 미리보기를 보존하지 않음.
- 안전정보는 단일 항목 편집만 구현했음. 계약의 복수 항목·자료 확인 시점·출처 자원 관리는 후속 작업임.
- 시연 객체는 실제 API 요청 본문과 다름. 변환 계층을 추가할 예정임.
- 사용자 지도는 정적 자료를 사용하므로 관리자 게시 결과를 반영하지 않음.
- AI 후보 생성은 연결 전임. 현재는 직접 입력·검수하는 방식임.

## 검증

관리자 서비스 테스트 22개를 작성했음. 잠금 독점·만료·본인 재개·오래된 화면의 저장 차단, 안전정보 충돌과 재검토, 게시 조건, 삭제 후 감사 이력 등을 검사함.

기존 브라우저 검수에서 대체 텍스트 보완 → 안전정보 충돌 재현 → 재검토 → 게시 → 이력 조회를 확인했음. 본인 잠금 재개의 브라우저 검수는 도구 연결 문제로 완료하지 못했으며 자동 테스트로 확인했음.

현재 저장소 정리에서는 코드 분리 후 빌드와 자동 검증을 수행함. 실제 API·DB 통합과 다중 연결 동시성은 후속 검증 대상임.
